css_class_definitions.ts

Built-in CSS class definitions combining composites, keyword classes, and token classes, and the definition types custom classes are authored with (CssClassDefinition, CssClassDefinitionInterpreter).

Token classes map to CSS variables (design tokens), and keyword classes are CSS value keywords that identify their property (flex, sticky). For other CSS values, use CSS-literal syntax like justify-content:center or overflow:hidden.

CssClassDefinitionBase import type {CssClassDefinitionBase} from '@fuzdev/fuz_css/css_class_definitions.js';

composite?

Whether the class is a composite, rendered in the fuz.utilities.composites sublayer beneath every single-purpose class, so a token or literal class on the same element always wins over the composite's declaration of the same property. Defaults to true for composes and ruleset definitions, false for a declaration without composes.

type boolean

late?

Whether the class orders late within its bucket: after every rule that ties with it on color scheme, media query, property rank, and state order, interpreted literals included, so display:flex hidden hides while a media query still outranks it (hidden md:flex shows at md and up). For an override that should win its ties whatever else names the same property, like hidden. Composites order by their registry position, which no two share, so the flag only reorders single-purpose classes.

type boolean

CssClassDefinitionInterpreter

CssClassDefinitionInterpreter import type {CssClassDefinitionInterpreter} from '@fuzdev/fuz_css/css_class_definitions.js';

Interpreter for dynamic CSS class generation based on pattern matching.

An interpreter sees a class name with its modifiers already stripped - md:hover:grid-cols-4 reaches it as grid-cols-4 - and returns a definition like a static one, so modifiers, ordering, and layering apply to what it returns the same as to a static class. A ruleset names the class it was given; the generator renames it to the full modified class. What an interpreter returns renders verbatim, so containing values built from class names found in markup is the interpreter's job.

Leading segments named like modifiers are stripped greedily, and the generator backs off one at a time, so an interpreter is offered the shortest base first: marker:none arrives as none before the full literal, since marker is also a pseudo-element modifier (cue likewise). A broad pattern shouldn't claim such a sub-base.
